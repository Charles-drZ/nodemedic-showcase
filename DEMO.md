# First Real NodeMedic Runtime Demo

This page records the first public runtime evidence generated by the working NodeMedic binary.

## Environment

- Date: September 10, 2026
- NodeMedic: `0.1.0-dev`
- Host OS: macOS (`darwin`)
- Architecture: arm64
- Docker CLI: not installed / not available on `PATH`

This is a real host run, not a fabricated Pi Node fixture.

## Install validation

The development build was installed into a writable bin directory already present on `PATH`. After installation, the bare command resolved normally:

```text
$ command -v nodemedic
/Users/<redacted>/.local/bin/nodemedic

$ nodemedic version
NodeMedic 0.1.0-dev
```

The public evidence intentionally redacts the local username/path component.

## Why this run matters

The run demonstrates the complete local path:

```text
real host collectors
  → normalized observations
  → deterministic rules
  → findings
  → terminal report
```

It also demonstrates an important failure-safety property: NodeMedic did not infer Pi Node, Horizon, peer, or port health when Docker evidence was unavailable. Those areas remained explicitly unobserved.

## What this run does not prove

This run does not prove the full Pi-specific path because the host did not have Docker/Pi Node installed.

The next public proof should run on a real Pi Node host and exercise:

- Pi Node container discovery
- official `node-status` services/protocol/Horizon/peer evidence
- Docker port mappings
- local Pi-port listeners

External reachability and CGNAT diagnosis remain out of scope until NodeMedic has a real external probe. Restart-loop diagnosis remains out of scope until local history exists.
